The first release of milestone 2: Linux and the Raspberry Pi 5, the groundwork for real cameras and stages, and stitching that corrects a stage's drift. It still runs the simulated microscope out of the box. README.md, in the zip or the archive, has the rest.

## Downloads

| Platform | Download | To start it |
|---|---|---|
| Windows x86_64 | `microscope-v0.2.0-windows-x86_64.zip` | Unzip it, and run `microscope-launcher.exe` |
| Linux x86_64 | `microscope-v0.2.0-linux-x86_64.tar.gz` | Unpack it, and run `./microscope-launcher` |
| Raspberry Pi 5, and Linux ARM64 | `microscope-v0.2.0-linux-arm64.tar.gz` | Unpack it, and run `./microscope-launcher` |
| Linux, as a service | `microscope_0.2.0_amd64.deb`, `microscope_0.2.0_arm64.deb` | `sudo apt install ./microscope_0.2.0_arm64.deb` |

- **The launcher** starts the server and opens the app in the browser. It keeps settings and data in `%LOCALAPPDATA%\Microscope`, or on Linux in `~/.local/share/microscope`.
- **The `.deb`** runs the microscope as a systemd service, started at boot. It serves <http://127.0.0.1:5000/> to that machine alone; README.md says how to open it to a network you trust.
- **The Windows files aren't signed yet.** Smart App Control may block them, and SmartScreen may warn.

## What's new since v0.1.1

- **Linux and the Raspberry Pi 5:**
  - builds for Linux x86_64 and ARM64;
  - the launcher on Linux;
  - a `.deb` that runs the server as a service.
- **Real hardware, the groundwork:**
  - each device runs on a thread of its own, and can be reconnected;
  - the camera SDKs aren't built in, but loaded when they're needed. Install them yourself: pylon for Basler cameras, Vimba X for Allied Vision's.
  - `microscope-server --list-devices` lists the serial ports and the cameras each SDK finds, for writing a configuration.
- **Zaber stages,** through Zaber's ASCII protocol: integrated stages, daisy-chained. They move, stop and home, and their speeds and accelerations are in Settings, Stage. `configs/zaber.json` and `configs/basler-zaber.json` are examples.
- **Basler cameras,** through pylon:
  - the live image and captures at full resolution;
  - exposure, gain, pixel format, white balance and binning;
  - calibration by the camera's automatic exposure and white balance;
  - reconnecting after a camera is unplugged.
- **Stitching that corrects drift:**
  - a scan's final mosaic places each image where its overlaps with its neighbours put it, not just where the stage said it was;
  - "Refine with image correlation", in the Slide Scan tab's Stitching settings, is on by default;
  - the gallery's viewer has a Corrections layer, with how far each image moved;
  - the scan's log says how many images moved, and the furthest;
  - the live preview keeps the stage's positions.
- **An accent colour to choose,** in Settings, Display: nine magentas, greens and blues. Each stays readable in both themes.
- **The simulator's stage can drift,** losing steps and creeping, to try the stitching's correction.

## Tried on hardware, and not yet

| Device or platform | Tried |
|---|---|
| Windows x86_64 | Yes, throughout |
| Linux x86_64 and ARM64 | On GitHub's Ubuntu runners only: builds, tests, the archives, and the `.deb`'s service |
| Raspberry Pi 5 | Not yet |
| Zaber stages | Not yet: against a scripted stand-in only |
| Basler cameras | On pylon's camera emulator; not yet on a camera |
| Allied Vision cameras | Vimba X loads and finds them; no driver yet |
| Sangaboard, and the Pi camera | Not yet |

## Not in this release

- **Allied Vision cameras, the Sangaboard and the Pi camera.**
- **Calibration and tuning on real microscopes,** and their performance on the Pi.
- **Sign-in.** The server has no password yet, so keep it to one machine or a network you trust.
- **The desktop app,** finding microscopes on the network, and signed installers.

## Upgrading from v0.1.x

Unzip or unpack it in place of the old one. Settings and data stay where they were, and settings saved by v0.1.x still load.
